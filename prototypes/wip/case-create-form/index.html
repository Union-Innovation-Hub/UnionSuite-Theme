What changes

  1. It says who the case is for. The member's name, number and type, with the standing badge the case page uses (new member, unfinancial, resigned). Opened from a note, the note shows under it and is linked to the case on save; its text starts the description without the "Created from Note:" prefix.
  2. Workplace (new): the member's jobs, current, not started and former, each with its employer, classification and dates, then "Not about a workplace". One current job is chosen for you; with several, nothing is, and it stays optional (the case's member card can change it later). No jobs: the field is not drawn.
  3. Subtype shows only when it applies: it fades in once a chosen type has subtypes, filtered from a list the prefill brings. No hidden buttons, session storage or one-second wait.
  4. Lead staff starts as you, and becomes required when access is Individual (the create flow already refuses that case without one, with a generic error).
  5. Who can see it is three buttons with a line saying what each means. Open stays the default.
  6. Gone: Status (a new case is New; sent as a hidden field), Workbench (the create flow never saves it) and the second Validate round trip. Priority starts at Normal, not Lowest. Date of incident starts empty (today was saved for cases about older events) and cannot be in the future.
  7. Every field shows at once, required ones marked. Today all fields are hidden until the prefill answers, then appear. The FormFields table can still hide fields or change what is required.
  8. Create case is never greyed out. Pressed with something missing, each missing field says what it needs and the first takes focus. While saving, the button spins ("Creating case…"); on success the page opens the new case, instead of a message with a link.

Kept as they are: the NoteOrdinal, InteractionOrdinal and ID (MemberID) URL parameters, CurrentDate, Module, Area, Prefill and the autoexecute prefill. Removed: CaseWorkBench, HiddenSubmitButton, SubTypeSession, SubTypeFire.

Flow changes

  • Case: Create-Prefill returns, beside ReqVals: the for line (member name, number, type, standing), the member's jobs (the workplace jobs IQA by member ID, as API - Manage Case - Primary Contacts Workplaces returns them by case), all subtypes with their parent tag (what Cases/SetSessionStorage returns now), the signed-in user's ID, and the note for the origin line. Both branches run the same FormFields query today; one is enough.
  • Cases: Create Case Staff saves PrimaryWorkplaceID (blank: not chosen; 0: not about a workplace) to iMIS and CloudToolz, and answers {CaseID, CaseNum} so the page can open the case. When the lead is the creator, one staff row (Primary), not two.
  • Its required check (type, status, description) stays as the safety net; Form/Validation is no longer called from this form.

To decide

  3. Cancel: back to the member's page (as here), or ask first when something has been typed?
  4. The staff list includes organisations (Pecan Street, Inc) and Hub Record: clean up the Get Staff Members IQA?
