Note and task form

One form, one order

  1. Note | Task at the top, beside the record. It is FollowUpRequired. Chosen before typing, so what it opens never moves text already written. Add note opens it on Note, Add task on Task (Type= in the address); a saved note opens on Note and can still be given follow-up.
  2. Task: What needs doing? (Title, required) and the flag, then Details (Note, optional, behind Add details on a new task), then Due date (with Add time once there is a date, in 15-minute steps, as the task form has it) and Assign to (optional). Saved as one Deadline datetime; with no time it is midnight, which reads back as the date alone.
  3. Note: Note (Note, required) first. The title and the task fields close.
  4. Switching keeps what's typed: a note's text becomes the task's details, and back, until it is saved.
  5. Editing a task: Completed, and under it What was done (ActionedNotes, optional), open once ticked or when it has text.
  6. A saved task stays a task (owner, 18 November 2026): editing one has no Note | Task choice.
  7. Tags, then Attachments and Access below a rule. Each new attachment picks its own attachment tags (the attachment tag list, not the note tags); a saved one shows its tags, changed through the attachment's own quick edit.
  8. Cases only for now. Personal tasks get a form of their own; agreements are parked (owner, 18 November 2026).
  9. Every change is logged against the record (LogChangesToIMIS, Table Zen_CloudFiles_Notes): an Add with what was set, an Edit with each column old → new.
  10. The save sends the row's columns: FollowUpRequired, Title, Note, ActionedNotes, Deadline, PrimaryStaffLead (Assign to), HighPriority, Actioned (Completed), Access, with the tags and the case's keys, to POST /cases/US/note (add and edit; owner, 18 November 2026). Saving closes the popup: no Save and add another.
